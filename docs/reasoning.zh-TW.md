# 思考過程：從規則到答案

[English version](reasoning.md)

本文依照實際推導的順序，整理這個專案背後的思考鏈。每一步都說明觀察到什麼、為什麼重要，以及它帶出了什麼結論。細節請見[方法說明](methodology.zh-TW.md)與程式碼；本文只講推理本身。

## 1. 真正隨機的是什麼

- 每次 spin，每條 reel 各自以相同機率停在任一位置，盤面顯示每條 reel 上連續 3 個符號。所以 9 個格子**不是** 9 次獨立抽樣：同一欄的 3 格，是同一條 strip 上相鄰的 3 個位置。
- 三條 reel 長度為 L₁、L₂、L₃ 時，總共恰好有 N = L₁ · L₂ · L₃ 種機率相同的結果，每個機率都是分母為 N 的分數。

**結論**：RTP 可以用窮舉精確算出，「RTP = 0.95」可以當成分數等式 RTP = 19/20 來檢查，沒有四捨五入，也沒有「差不多」。模擬只用來交叉驗證。

## 2. 規則沒有說清楚的地方

計算之前，先把必須自行決定的解讀寫下來（README 的[假設](../README.zh-TW.md#假設)）：

- 停止位置均勻且互相獨立，盤面在 strip 尾端接回開頭。
- 一次 spin 同時中多個型態時，payout **加總**，因為規則是對每個型態分別定價。
- 全盤中獎時，4 個 2×2 型態也同時成立。依照上一點加總（9 倍）是最一致的解讀，所以作為主要版本（`sum_all`）。只計全盤（5 倍）也說得通，因此另外交付這種解讀下的配置（`full_only`），而不是只押其中一種。
- 「中獎」定義為 payout > 0；另外也報告 payout > 押注 的結果。

## 3. 兩個讓問題變小的觀察

**(a) 每個中獎型態都包含中心格。** A、B、C、D、E 都包含第 2 列第 2 欄。所以一次 spin 中所有中獎的型態，顯示的一定是同一個符號，也就是中心格的符號。不同符號的中獎不會混在一起，各符號的統計可以直接相加。

**(b) 2×2 型態就是兩個相鄰欄各自的「上下成對」。** 型態 A 以符號 x 中獎，若且唯若第 1 欄的第 1、2 列都是 x，**而且**第 2 欄的第 1、2 列也都是 x。所以一欄只透過兩件事影響結果：上方兩格是否成對、是哪個符號，以及下方兩格是否成對、是哪個符號。顯示 x, x, x 的欄兩者都成立。

在一條 reel 上，「盤面上方兩格是一對 x」的停止位置數，正好等於 strip 上相鄰 x, x 的個數（循環計算）；「x, x, x」的停止位置數，正好等於相鄰三連 x 的個數。因此：

> 遊戲的所有統計量（RTP、勝率、各型態的機率）只取決於每條 reel 的長度，以及每個符號相鄰**成對**與**三連**的數量。strip 除此之外怎麼排列，都不影響結果。

令 reel i 上 aᵢ(x) = 成對數 / Lᵢ、tᵢ(x) = 三連數 / Lᵢ，m(x) 為倍率，`sum_all` 的 RTP 為

```
RTP = Σₓ m(x) · 2 · a₂(x) · (a₁(x) + a₃(x))   +   5 · Σₓ m(x) · t₁(x) · t₂(x) · t₃(x)
      型態 A + C 用 reel 1–2，                     全盤
      型態 B + D 用 reel 2–3
```

中間的 reel 出現在每一項：它參與全部 5 種型態。

## 4. 最簡單的解

要經常中獎，最便宜的做法是用倍率最低的符號 0（0.25 倍）。以它為基礎最簡單的 reel 家族：

- 中間 reel 全是 0，所以永遠同時有上方與下方的一對 0；
- 外側兩條 reel 各有一段連續 k 個 0，後面接幾個不重複的其他符號。

連續 k 個 0 提供 k − 1 個成對與 k − 2 個三連，所以上面的公式變成

```
RTP = (k₁ − 1) / (2L₁) + (k₃ − 1) / (2L₃) + (5/4) · (k₁ − 2)(k₃ − 2) / (L₁L₃)
```

掃描小整數後，最小的解是 L₁ = 5、k₁ = 4、L₃ = 10、k₃ = 8：

| Reel | Strip |
|---|---|
| 1 | `[0, 0, 0, 0, 1]` |
| 2 | `[0, 0, 0]` |
| 3 | `[0, 0, 0, 0, 0, 0, 0, 0, 1, 2]` |

它的 5 × 3 × 10 = 150 種結果可以手算驗證：

- Reel 1 的 5 個停止位置中，上方一對 0 出現 3 次、下方一對 0 出現 3 次、三個 0 出現 2 次。
- Reel 3 的 10 個停止位置中，上方一對 0 出現 7 次、下方一對 0 出現 7 次、三個 0 出現 6 次。
- Reel 2 永遠顯示三個 0。

所以 P(A) = P(C) = 3/5、P(B) = P(D) = 7/10、P(E) = 2/5 × 6/10 = 6/25，因此

```
RTP = 0.25 × (3/5 + 7/10 + 3/5 + 7/10) + 1.25 × 6/25 = 0.65 + 0.30 = 0.95
```

只有在兩條外側 reel 都沒有一對 0 時才不會中獎，機率為 1/5 × 2/10 = 1/25，所以勝率為 24/25 = 96%。

這已經精確回答了題目，也就是最先建構並驗證的[概念驗證](poc.md)（英文；[`configs/poc_reels.json`](../configs/poc_reels.json)）。

## 5. 先確認答案正確

在改進之前，答案必須可信，而手推的公式很容易出錯。所以用三種方式檢查：

- 精確評估器：以分數窮舉每一種停止位置組合；
- 單純的暴力窮舉：逐一跑過每個停止位置，在數百組隨機 reel 上與精確評估器比對；
- Monte Carlo 模擬：獨立檢查精確結果是否合理。

## 6. 檢討這個答案

最小解是正確的，但它不像一個遊戲：96% 的 spin 都中獎、所有中獎都是符號 0、符號 1–4 從不賠付、中間 reel 只有一種符號。於是把這些問題寫成明確的要求（[方法說明第 1 節](methodology.zh-TW.md#1-符號與要求)）：

- **硬性要求**：RTP 精確等於 19/20、勝率 ≥ 55%、每個符號都貢獻部分 RTP、每個型態都可能中獎、每條 reel 都包含全部 5 種符號。
- **偏好（依優先順序）**：倍率越高越難中（S1）；每個符號都可能全盤（S2）；勝率介於 0.55 到 0.70（S3）；每條 reel 最多 150 個符號（S4）。

## 7. 搜尋前先推理：這些要求逼出了什麼

- 中獎 spin 的平均 payout 等於 RTP / 勝率。勝率介於 0.55 到 0.70 時，中獎 spin 平均要賠 1.36 到 1.73。
- 符號 0 必須是最常中獎的符號（S1）。沒有全盤時，一次 spin 最多只能完成 3 個 2×2 型態（已對所有盤面暴力檢查），所以沒有全盤的符號 0 中獎最多只賠 0.75。`sum_all` 下全盤的 0 賠 9 × 0.25 = 2.25。
- 所以除非符號 1–4 經常中獎（S1 不允許），全盤的 0 就必須很常見，這需要三條 reel 上都有很長的連續 0。

**預測**：最終的 reel 會以很長的連續 0 為主，而且全盤不會罕見。搜尋結果證實了這兩點：最終的 `sum_all` 配置中，全盤出現在 32.5% 的 spin（約佔中獎 spin 的一半、RTP 的 43%），符號 0 提供了 91% 的 RTP。

`full_only` 下符號 0 中獎最多賠 1.25。勝率最多 0.70 時，符號 0 最多只能提供 0.95 中的 0.875，其餘必須由符號 1–4 提供，同時又要比 0 更少中獎。在每條 reel 最多 150 個符號的範圍內，搜尋找不到這樣的設計，所以 `full_only` 配置保留 S1、放棄 S3（勝率 85.3%）。

## 8. 搜尋整數，而不是搜尋 strip

因為只有成對與三連的數量會影響結果（第 3 步），一個設計只是每條 reel 少數幾個整數，而不是 150 個符號的 strip。

1. 對這些計數做模擬退火，在遵守要求優先順序的前提下接近 0.95。
2. 接著把結果調到精確，這只是整數運算：20 · N · RTP 必為整數。固定兩條 reel 時，它是第三條 reel 計數的仿射函數，所以可以直接解出讓它剛好等於 19 · N 的計數。
3. 把計數排成同一符號連續區段互不相鄰的 strip，再用精確評估器重新檢查。

## 10. 限制與後續方向

- 搜尋是啟發式方法：它找得到合法的設計，但無法證明是最佳解，而且 `full_only` 的結果會隨種子改變。
- 真實感受限於規則本身（第 7 步）。在這組型態與倍率下，要在 RTP 0.95 時維持 55–70% 的勝率，就必須讓最便宜的符號經常全盤。
- 如果有更多時間：在允許更長 reel 的情況下，畫出勝率與全盤頻率之間的取捨；並嘗試讓更嚴格的勝率定義（payout > 押注）也達到 55%。
