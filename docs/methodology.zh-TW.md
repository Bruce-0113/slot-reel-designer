# 方法說明

[English](methodology.md) | 繁體中文

本文說明 [`configs/`](../configs) 中最終 reel 配置的設計與驗證方式：精確評估器、搜尋所依據的計數模型、搜尋與精確收尾、strip 的建構、兩種 payout 模式，以及驗證方法。結果本身請見 [README](../README.zh-TW.md#結果) 與 [PAR sheet](par-sheet.zh-TW.md)。

> **先有概念驗證。** [`docs/poc.md`](poc.md)（英文）先建立一組刻意簡化的 reel 家族（中間 reel 全為 0），證明 RTP 可以精確達到 19/20，並把整條流程跑過一遍。它的缺點（所有中獎都在符號 0、勝率 96%、只有 150 種結果）正是下列額外要求的由來。

---

## 1. 符號與要求

- 第 i 條 reel 長度為 L<sub>i</sub>，以相同機率停在 s<sub>i</sub>；該欄由上到下顯示 r<sub>i</sub>[s<sub>i</sub>]、r<sub>i</sub>[s<sub>i</sub>+1]、r<sub>i</sub>[s<sub>i</sub>+2]，index 取 mod L<sub>i</sub>。
- 總共有 N = L<sub>1</sub>·L<sub>2</sub>·L<sub>3</sub> 種機率相同的 *spin*（stop 組合）。押注為 1。
- m(x) 為符號 x 的倍率：`{0: 1/4, 1: 11/20, 2: 1, 3: 3, 4: 5}`。型態 A–D（2×2 方塊）派彩 m(x)，E（全盤）派彩 5·m(x)。
- *勝率* = P(payout > 0)；*勝率（payout > 押注）* = P(payout > 1)。

題目只規定 RTP 與勝率。最終配置還必須像一款真正可玩的遊戲，因此依下列要求設計（[`search.py`](../slot_reel_designer/search.py) 中的 `check_requirements` 與 `check_preferences`）：

| | 要求 | 類別 |
|---|---|---|
| H1 | 在該設定檔的 payout 模式下，RTP 精確等於 19/20 | 必要 |
| H2 | 勝率 ≥ 11/20 | 必要 |
| H3 | 符號 0–4 都對 RTP 有貢獻 | 必要 |
| H4 | 型態 A–E 都有機會中獎 | 必要 |
| H5 | 每條 reel 都包含全部 5 種符號（因此不會整條都是同一個符號） | 必要 |
| S1 | 倍率越高的符號，spin 在該符號中獎的機率越低，就像真正的賠率表 | 偏好 1 |
| S2 | 每個符號都可能出現全盤 | 偏好 2 |
| S3 | 勝率落在 [0.55, 0.70]，是合理的數值，而不是幾乎每次都中 | 偏好 3 |
| S4 | 每條 reel 最多 150 個符號，strip 仍然容易閱讀 | 偏好 4 |

必要條件以 `Fraction` 精確檢查。偏好依優先順序排列；搜尋時會犧牲較低的偏好來換取較高的偏好。

## 2. 精確評估器

程式：[`evaluator.py`](../slot_reel_designer/evaluator.py)。

**暴力窮舉（參考實作）。** `evaluate_bruteforce` 為 N 種 spin 逐一建立盤面，並用 [`game.py`](../slot_reel_designer/game.py) 的遊戲規則計分。它是「正確」的定義，但計算量隨 N 成長。

**盤面欄位計數。** 一條 reel 的 stop 只透過它顯示的那一欄（上、中、下）影響結果，所以每條 reel 先化簡成各種不同欄位的出現次數（`window_counts`）。不同的欄位最多 5³ = 125 種；最終配置每條 reel 只有 15 到 19 種。一組（左、中、右）欄位組合代表 左次數 × 中次數 × 右次數 種 spin。

**空白欄合併。** 固定中間欄。凡是碰到外側欄的型態，都包含一個由該外側欄與中間欄組成的 2×2 方塊（左側為 A、C，右側為 B、D，E 則包含全部）。因此，一個與中間欄組不成任何 2×2 方塊的外側欄，不會參與任何中獎，所有這類外側欄的計分都相同。它們被合併成一個不與任何符號相符的 *空白* 欄，次數為它們的總和。中間欄若含有成對符號，每一側最多保留 9 種外側欄加上空白欄；若不含成對符號，則只剩空白欄。因此無論 reel 多長，需要計分的盤面最多為 125 × 10 × 10 個。測試以長度 2,000、2,500、3,000 的隨機 reel（1.5 × 10¹⁰ 種 spin）在 2 秒限制內完成精確評估。

`outcome_counts` 回傳每一組（型態、符號）中獎組合背後的 spin 數。其餘結果都以整數與 `Fraction` 由它推得：`evaluate`（RTP、勝率、payout > 押注的勝率、各型態與各符號的數字）、`payout_distribution` 與 `payout_variance`。整個過程不使用浮點數，因此「RTP == 19/20」是精確的相等判斷。

## 3. 計數模型：每條 reel 16 種狀態

程式：[`search.py`](../slot_reel_designer/search.py) 的「count model」區段。

### 狀態

對停在 s、顯示 (a, b, c) 的一條 reel，定義

```
T = a if a == b else None     （第 0–1 列成對）
U = b if b == c else None     （第 1–2 列成對）
```

T 與 U 只有在 a = b = c 時才會同時有值，因此每個 stop 屬於 16 種狀態之一：(None, None)，以及每個符號各自的 (x, None)、(None, x)、(x, x)。

### 每個型態都是狀態的條件

令 T<sub>i</sub>、U<sub>i</sub> 為第 i 條 reel 的狀態：

| 型態 | 以符號 x 中獎的充要條件 |
|---|---|
| A（左上） | T<sub>1</sub> = T<sub>2</sub> = x |
| B（右上） | T<sub>2</sub> = T<sub>3</sub> = x |
| C（左下） | U<sub>1</sub> = U<sub>2</sub> = x |
| D（右下） | U<sub>2</sub> = U<sub>3</sub> = x |
| E（全盤） | 三條 reel 都是 T<sub>i</sub> = U<sub>i</sub> = x，也就是每一欄都是 (x, x, x) |

例如 A 的格子是 reel 1 與 reel 2 的第 0–1 列，它們全部顯示 x，若且唯若兩條 reel 在第 0–1 列都有一對 x。

### 單條 reel 的狀態分布只取決於計數

對長度為 L 的循環 strip r 與符號 x，令

```
pairs(x)   = #{i : r[i] = r[i+1] = x}              （成對數）
triples(x) = #{i : r[i] = r[i+1] = r[i+2] = x}     （三連數；index 取 mod L）
```

則在該 reel 的 L 個 stop 中：

| 狀態 | Stop 數 |
|---|---|
| (x, None) | pairs(x) − triples(x) |
| (None, x) | pairs(x) − triples(x) |
| (x, x) | triples(x) |
| (None, None) | 其餘 |

**證明概要。**

1. T(s) = x 若且唯若 s 是 x 的成對位置，所以有 pairs(x) 個 stop 的 T = x。
2. U(s) = x 若且唯若 s + 1 是 x 的成對位置。位移 s ↦ s + 1 是循環 index 集合上的一對一對應，所以同樣有 pairs(x) 個 stop 的 U = x。
3. T(s) = U(s) = x 若且唯若 r[s] = r[s+1] = r[s+2] = x，所以有 triples(x) 個 stop 兩者皆成立。T = x 而 U = y ≠ x 不可能發生，因為兩者指的都是中間的符號 r[s+1]。
4. 由排容原理即得上表。
5. 各 reel 獨立且均勻地停止，所以三個狀態互相獨立，各自服從上述分布。每個型態是否中獎都是這三個狀態的函數，每次的 payout 也是。因此所有中獎事件的聯合分布只取決於 L<sub>i</sub>、pairs<sub>i</sub> 與 triples<sub>i</sub>：RTP、勝率、payout > 押注的勝率、各型態與各符號的數字，以及整個 payout 分布都是如此。∎

**推論：排列方式不影響結果。** 兩條長度、成對數與三連數都相同的 strip，無論連續區段放在哪裡、順序如何，統計結果都完全相同。一組 reel 配置可以完整地用 3 × 11 個整數描述，`evaluate_counts` 從 16³ = 4,096 種狀態組合精確算出結果。測試確認它的每一個欄位都與 `evaluate` 相同。

### 封閉公式

令 a<sub>i</sub> = pairs<sub>i</sub>(x) / L<sub>i</sub>、t<sub>i</sub> = triples<sub>i</sub>(x) / L<sub>i</sub>。由獨立性，P(A 以 x 中獎) = P(C 以 x 中獎) = a<sub>1</sub>a<sub>2</sub>，P(B) = P(D) = a<sub>2</sub>a<sub>3</sub>，P(E) = t<sub>1</sub>t<sub>2</sub>t<sub>3</sub>，因此

```
RTP = Σ_x m(x) · [ 2·a2·(a1 + a3) + w·t1·t2·t3 ]        w = 5（sum_all）、1（full_only）
```

w 是全盤在其 4 個 2×2 方塊之外額外增加的部分；這 4 個方塊已經算在第一項裡（見第 6 節）。

**精確性只是整數運算。** 20·m(x) 都是整數（5、11、20、60、100），所以

```
20·N·RTP = Σ_x 20·m(x) · [ 2·P2·(P1·L3 + P3·L1) + w·T1·T2·T3 ]      （P = pairs(x)，T = triples(x)）
```

是整數，而 RTP = 19/20 若且唯若它等於 19·N。最終配置中，這個值是 48,579,960 = 19 × 2,556,840（sum_all）與 55,866,954 = 19 × 2,940,366（full_only）。

**各符號的中獎機率（用於 S1）。** 每個型態都涵蓋中間欄，而中間欄的狀態最多只指向一個符號，所以一次 spin 最多只在一個符號上中獎，各符號的中獎機率加總即為勝率。令 p = a − t、b = 2a − t = P(T = x 或 U = x)：

```
P(spin 在 x 上中獎) = 2·p2·[1 − (1 − a1)(1 − a3)] + t2·[1 − (1 − b1)(1 − b3)]
```

`rtp_numerator` 與 `symbol_hit_numerators` 精確計算這些值，`fast_stats` 則是搜尋內層迴圈使用的浮點數版本。

## 4. Strip 的建構

程式：[`search.py`](../slot_reel_designer/search.py) 中的 `ReelSpec` 與 `build_strip`。

既然只有計數有影響，搜尋就在連續區段層級的描述上進行，最後才建構 strip。`ReelSpec(runs, extra, singles)` 對每個符號 x 記錄 `runs[x]` 個長度 ≥ 2 的連續區段，這些區段在長度 2 之外合計多出 `extra[x]` 個符號，另外還有 `singles` 個單獨符號。長度 k ≥ 2 的連續區段貢獻 k − 1 個成對與 k − 2 個三連，單獨符號則不貢獻，前提是相鄰的連續區段（含頭尾相接處）符號不同。因此

```
L = Σ_x (2·runs[x] + extra[x]) + singles      pairs[x] = runs[x] + extra[x]      triples[x] = extra[x]
```

全都是這 11 個計數器的線性函數。

`build_strip` 的排列步驟：

1. **單獨符號。** 沒有連續區段的符號先各分到一個單獨符號。其餘的單獨符號依序分給項目（連續區段加單獨符號）最少的符號，同數時給較高的符號。
2. **區段長度。** 同一符號的多個連續區段平均分攤多出的符號，長短區段交錯排列。
3. **循環順序。** 排列各項目，使同一符號的兩個項目永遠不相鄰（包括頭尾相接處）。這件事可行的充要條件是沒有任何符號佔超過一半的項目（`is_buildable`）。程式使用貪婪排序（剩餘項目最多者優先，且不與前一個符號相同）。它在所有試過的計數向量上都成功，但這一點未經證明，所以仍會檢查其結果，並保留交錯填入（先填位置 0、2、4…，再填 1、3…）作為備案；在上述條件下，交錯填入必定成功。
4. **檢查。** 重新計算建好的 strip 的成對數與三連數，必須與 spec 相同，否則建構失敗。

例如 sum_all 配置的 reel 1 是 `0×50 1×9 4×3 0×50 1×9 2×5 3×3 4×1`（符號×長度，最後接回第一個區段）。

## 5. 搜尋與精確收尾

程式：[`search.py`](../slot_reel_designer/search.py) 的「search」與「exact finish」區段。執行方式為 `python -m slot_reel_designer.solve`。

### 搜尋範圍

每條 reel 對每個符號都至少有一個長度 ≥ 3 的連續區段（`runs[x] ≥ 1` 且 `extra[x] ≥ 1`），最多 150 個符號，而且必須能建構成 strip。每條 reel 上每個符號都有三連，代表每個符號都可能出現全盤（S2），H3、H4、H5 也隨之成立。

### 目標函數

搜尋要最小化 `Objective.penalty`，其權重依優先順序設定（h<sub>x</sub> = P(spin 在 x 上中獎)）：

| 項目 | 權重 | 目的 |
|---|---:|---|
| \|RTP − 0.95\| | 1000 | H1（精確值交給收尾步驟） |
| max(0, 0.555 − 勝率) | 1000 | H2，保留一點餘裕 |
| 每個 x 的 max(0, 1.03 − h<sub>x</sub>/h<sub>x+1</sub>) | 200 | S1：中獎頻率嚴格遞減 |
| 每個 x 的 max(0, 1.25 − h<sub>x</sub>/h<sub>x+1</sub>) | 5 | S1：像賠率表一樣拉開間距 |
| ln(max<sub>x</sub> h<sub>x</sub>/h<sub>x+1</sub>) | 1（full_only 為 0） | S1：平緩地遞減 |
| 勝率超出 [0.56, 0.69] 的距離 | 50 | S3，保留一點餘裕 |
| \|勝率 − 0.60\| | 1 | 勝率接近 0.60 |
| (L<sub>1</sub> + L<sub>2</sub> + L<sub>3</sub>) / 450 | 0.3 | S4：reel 越短越好 |

S2、S4 的長度上限與 H3–H5 則由搜尋範圍直接保證。

### 模擬退火

- 共 10 次，亂數種子依序為 `seed`、`seed + 1`…，每次 60,000 步；溫度以等比方式從 3 降到 10⁻³，並以 Metropolis 規則決定是否接受。
- 每一步修改一條 reel 的 spec：改變一個計數器、把多出的符號從一個符號移到另一個符號，或在單獨符號與某個符號的多出符號之間互換。
- **修補。** 固定其他 reel 時，RTP 可寫成該 reel 長度 L 的 A / L + B（中間 reel 的 B = 0），而只改變該 reel 的單獨符號數只會改變 L。因此每一步之後，都以封閉公式重新求出每條 reel 的單獨符號數，讓 RTP 在搜尋範圍內盡量接近 0.95，並以三組修補結果中最好的一組作為提案。這讓搜尋路徑一直停在目標 RTP 附近。
- 迴圈使用浮點數版本的封閉公式（`fast_stats`）；只有收尾步驟使用精確整數。

### 精確收尾

模擬退火能接近 0.95，但很少剛好落在 19/20。收尾步驟從最好的 3 個退火結果出發，讓 RTP 變成精確值。

1. 定義 *超出量* E = 20·N·(RTP − 19/20) = 20·N·RTP − 19·N。它是整數，且 H1 成立若且唯若 E = 0（`rtp_excess`）。
2. 選一條 reel 作為 *樞紐*，固定另外兩條。20·N·RTP 與 N 對每條 reel 的長度、成對數、三連數都是線性的，而這些又是 spec 計數器的線性函數，所以 E 是樞紐計數器的仿射函數：E = f<sub>0</sub> + c·v + γ·singles，其中 v 為 5 個區段數與 5 個多出符號數（`excess_coefficients`）。
3. 列舉鄰近範圍：樞紐的區段數 ±2、多出符號數 ±3（10 以上則 ±12），另外兩條 reel 的單獨符號數 ±4。
4. **中間相遇法。** 把樞紐的 10 個計數器分成兩組，每組 5 個，用 numpy 列舉每組的部分和 c·v。E = 0 需要 f<sub>0</sub> + S<sub>a</sub> + S<sub>b</sub> ≡ 0 (mod |γ|)，因此 B 組的部分和依餘數分桶，A 組的每一列查找對應的桶。每個配對都精確決定單獨符號數 singles = −(f<sub>0</sub> + S<sub>a</sub> + S<sub>b</sub>) / γ；若它 ≥ 0 且 spec 在搜尋範圍內，就保留下來。
5. 每條 reel 輪流擔任樞紐。勝率低於 11/20 的候選會被剔除（H2，由計數精確檢查；H3–H5 已由搜尋範圍保證），因此留下的候選都滿足全部必要條件。這些候選依不含 RTP 項的懲罰值排序，最好的一組建構成 strip，再用 `evaluate` 重新檢查；若結果不一致，搜尋會直接報錯。

以種子 0 執行時，收尾步驟在 sum_all 找到 9,286 個精確候選（選中者的懲罰值 2.6233），在 full_only 找到 2 個（懲罰值 9.2532）。同一個種子的搜尋結果是確定的：以預設參數執行 `python -m slot_reel_designer.solve`，會逐位元組重現兩個已提交的設定檔，耗時約 26 秒（sum_all）與 18 秒（full_only）。

`--seed N` 以種子 N 到 N + 9 進行模擬退火，因此相鄰的種子共用 10 次中的 9 次。結果取決於種子。full_only 的精確候選很少，S1 在種子 0 下成立，但例如在種子 100 或 1000 下就不成立；不過 `solve` 儲存的設定檔一定滿足 H1–H5。逐位元組重現只在一個環境上檢查過（arm64 的 macOS、Python 3.12.8、numpy 2.5.4）：模擬退火由浮點數運算（`fast_stats`、`math.exp`、`math.log`）引導，因此在其他平台上可能得到不同的 strip，而 `verify` 仍會精確檢查它們。

## 6. 兩種 payout 模式

全盤中獎時，4 個 2×2 方塊也同時成立，而題目沒有說明這些方塊是否也要派彩（README 假設 3）。程式支援兩種解讀（[`game.py`](../slot_reel_designer/game.py) 中的 `PayoutMode`）：

| 模式 | x 的全盤派彩 | RTP 公式中的 w | 設定檔 |
|---|---|---:|---|
| `sum_all`（主要） | 4·m(x) + 5·m(x) = 9·m(x) | 5 | [`configs/reels.json`](../configs/reels.json) |
| `full_only`（替代） | 5·m(x) | 1 | [`configs/reels_full_only.json`](../configs/reels_full_only.json) |

- **中獎相同，派彩不同。** 哪些型態中獎與模式無關，所以同一組 reel 在兩種模式下的勝率與各型態中獎機率都相同；不同的是 RTP、payout 分布與 payout > 押注的勝率。
- **同一組 reel 無法兼顧兩種模式。** sum_all 配置在 full_only 下的 RTP 為 3976079/6392100 ≈ 0.622030，full_only 配置在 sum_all 下的 RTP 為 9595777/5880732 ≈ 1.631732。因此兩種模式各自搜尋、各有一個設定檔。
- **為什麼 full_only 的勝率較高。** 在符號 0 上中獎的 spin，若不是全盤，最多只派 0.75，因為 4 個方塊同時中獎會迫使每一欄都是 (0, 0, 0)。若是全盤，sum_all 派 2.25，full_only 只派 1.25。在 S1 之下，最便宜的符號 0 最常中獎，也承擔大部分的 RTP。在 full_only 下，它最多只能提供 1.25 × 勝率，勝率 0.70 時為 0.875，其餘部分就必須來自更少中獎、倍率更高的符號。搜尋找不到同時滿足 H1、H2、S1、S2 且勝率落在 S3 區間內的 full_only 配置。由於 S1 與 S2 的優先順序較高，full_only 配置保留它們，接受 0.853421 的勝率。在這組配置中，84.88% 的 spin 在符號 0 上中獎，符號 0 提供了 0.95 RTP 中的 0.939766。
- **全盤並不罕見。** 在真實的賠率表中，全盤是罕見的頭獎。S1–S4 沒有這項要求，而在這裡全盤很常見，而且幾乎都是符號 0：sum_all 下全盤出現在 32.5% 的 spin（約每 3.08 次一次，約佔中獎 spin 的一半，貢獻 43% 的 RTP），full_only 下則為 68.2%（佔中獎 spin 的 80%，貢獻 90% 的 RTP）。原因是每條 reel 上符號 0 的連續區段都很長，而勝率下限（H2）與 S1 會把搜尋推向這種配置：大部分中獎必須落在符號 0，而它的 2×2 方塊每個只派 0.25，所以搜尋主要靠符號 0 的全盤達到 0.95。

## 7. 驗證

所有報告的數字都是精確值，每一層都有另一個獨立方法檢查。

1. **精確窮舉。** `evaluate` 以 `Fraction` 涵蓋每個設定檔的全部 N 種 spin，`check_requirements` 精確檢查 H1–H5。`python -m slot_reel_designer.verify` 會印出這些數字，`python -m slot_reel_designer.report` 則用同一個評估器產生 [PAR sheet](par-sheet.zh-TW.md)。
2. **暴力窮舉交叉驗證。**
   - 在 100 組隨機的小型 reel 上，`evaluate` 與 `evaluate_bruteforce` 在兩種模式下的每一個欄位都相同。payout 分布與中獎組合計數也以相同方式檢查。
   - 在長度 2,000、2,500、3,000 的隨機 reel 上，RTP 與另一個由各欄機率獨立推導的公式相同。
   - 在 150 組隨機 reel 上，計數模型與 `evaluate` 在兩種模式下的每一個欄位都相同；在較小的 reel 上也與 `evaluate_bruteforce` 相同。狀態計數與 300 條隨機 strip 的實際盤面欄位相符，封閉公式也與模型相符。
   - 對兩個最終設定檔，另一個直接依 9 個格子與型態定義撰寫、以 numpy 窮舉全部 stop 組合的獨立實作，重現了 `Evaluation` 的每一個欄位。另有一個 slow 測試以 `evaluate_bruteforce` 跑完全部 2,556,840 與 2,940,366 種 spin。
3. **Monte Carlo 模擬**（[`simulate.py`](../slot_reel_designer/simulate.py)）。以 numpy 的預設亂數產生器獨立、均勻地抽出 stop。Payout 以押注的 1/20 為單位計算，都是整數，所以總和是精確的。每個估計值都附上 95% 信賴區間，即估計值 ± 1.96 個標準誤。`verify` 只在估計值與精確值相差超過 4 個標準誤時判定失敗：95% 信賴區間本來就有 1/20 的機率沒涵蓋真實值，若以此判定失敗，正確的設定檔約有 10% 的機率被判失敗。精確值是否落在區間內仍會印出。以 n = 10⁷ 次 spin（種子 0，每個設定檔約 0.4 秒）模擬時，每個精確值都落在對應的信賴區間內；z 值為 +0.16、−0.33、+0.45（sum_all 的 RTP、勝率、payout > 押注的勝率）與 −0.76、−0.22、−0.50（full_only）。數字見 [README](../README.zh-TW.md#結果)。
   - 模擬器在 60 組隨機 reel 的每一個 stop 上、兩種模式下，單次 spin 的 payout 都與 `evaluate_grid` 相同。在每種模式 20 組小型隨機 reel 上，以及兩個設定檔各 200,000 次 spin 下，估計值都落在精確值的 4 個標準誤以內。
4. **測試。** 共 2,530 個測試：預設執行 2,523 個，只需幾秒；另有 7 個標記為 `slow`（`pytest -m slow`，需要幾分鐘）。slow 測試會重跑兩個設定檔的搜尋、以預設參數執行 `solve` 並逐位元組比對兩個檔案、以暴力窮舉檢查兩個設定檔，並重跑概念驗證的 `scan(40)`。其他測試涵蓋 strip 建構（300 組隨機 spec、兩種項目排序在每個分量 1 到 6 的計數向量上的結果、單一符號的項目排列，以及由連續區段描述重建每條已提交的 reel）、精確收尾（仿射關係、一個剛好落在 19/20 的設計案例、還原被擾動的解）、各要求檢查的邊界情況、命令列工具的結束代碼、已提交的 PAR sheet 與重新產生的內容一致，以及 README 與本頁引用的數字（結果表格、模擬估計值與 z 值、第 3 與第 6 節的數字）與程式算出的結果一致。
